# 流体和源质库存

库存页面可切换物品、流体、源质。默认仅显示已确认有库存的资源；“全部名单候选”包含尚未查询和已确认数量为零的资源。NESQL 导出只提供身份、中文名称和纹理，数量必须来自 OC 的认证观测。

流体按注册名查询，显示 mB；源质按 aspect tag 查询，显示源质量。仅接纳 NESQL 名单中的无 NBT 身份。物品上的源质组成不是网络库存。三类数量分别统计；现有主页总量和库存趋势继续统计物品。

管理员在已启用 NESQL 无 NBT 物品名单的协作网络上调用 `POST /api/v1/networks/{network}/inventory-profile/resources`，幂等注册流体和源质名单。此操作不会重置物品扫描进度、启用时间和历史。新版 OC 明确上报 `fluids` / `essentia` 能力后，才会收到对应任务。旧版 OC 继续同步物品。

## 流体下单

支持 NESQL 无 NBT 流体的精确配方核验与额外合成。主 OC 需更新后重新上报 `craft_fluids`；副 OC 继续只读数量。主 OC 只使用 `getCraftable({name=registry,amount=0,size=1},"fluid")`，不会枚举配方。返回配方后再次检查产物名称与无标签身份。

在流体分类中选择已确认有配方的资源即可加入清单或立即提交，数量输入为 **mB**，默认 `1000`，即一桶。库存为零但已有配方的流体在“全部名单候选”中查看。主 OC 会给已查询过的流体核验配方；未确认时保留未知状态。支持玩家署名、指定 CPU、批量任务、幂等请求、断线待核对和完成后精确复核。

混合清单分别汇总物品件数和流体 mB，不把两种单位相加。合成表示请求额外生产输入数量，沿用 AE 的配方批量规则。源质目前仍仅查看库存。

主 OC 每个后台包至多核验一个配方，物品与流体交替，核验仍消耗原有四个读额度并受五秒 OC 间隔限制。旧版主 OC 不能收到流体配方或流体命令，已保存流体任务在能力恢复后继续；副 OC 不能执行配方核验或合成。

## NBT 变种

库存默认按注册名和 metadata 归组，点击后按需读取具体变种。父级总量只用于展示；清单、订单、精确查询和配方仍绑定具体物品 ID。原无 NBT 库存统计与历史保留原口径，NBT 候选、已查数量和库存单独显示。

管理员调用 `POST /api/v1/networks/{network}/inventory-profile/variants`（JSON `{}`）增量导入 NESQL 的带类型 NBT 记录。导入只建立候选，不证明有库存。新 OC 通过 `exact_nbt` 和 `max_nbt_bytes` 上报支持范围；旧 OC 继续只查无 NBT 物品。NBT 仍使用完整身份精确查询，共用原有预算和有界队列，确认零库存的候选降低查询频率。有库存变种才参加后台配方核验。

列表不传原始标签；显示名、标签摘要和身份摘要用于选择，完整带类型数据在详情中按需读取。图标优先采用 NESQL 精确变种，缺失时使用基础物品图标并标记 `base_fallback`。任意改名、基因组合等未导出身份不会自动从全网发现。

未收录物品可用样本登记：把样本放进普通箱子，连接 OC 转运器或库存控制器，启动更新后的桥接程序，然后执行 `ae-orbit-register north 1`。`north` 是箱子相对组件的方向，`1` 是槽位。命令读取一个实物槽位并登记身份，不移动物品、不把箱子数量计入 AE。登记后可在“全部名单候选”找到，数量等待 AE 精确观测。服务器需允许 OC 物品检查和完整 NBT 访问；拿不到标签时登记失败并保留未知状态。

CPU 监控的最终产物使用同一份 NESQL 纹理和本地纹理包。新版主 OC 从已有 `finalOutput()` 保留类型、metadata 与是否含标签，不上传标签内容、不额外读取 ME。无标签产物按身份匹配；旧版快照缺少 metadata 时，仅接纳唯一名称/显示名匹配。无法确定的产物保留占位图标。流体产物数量显示 mB。

## 更新 OC

在主 OC 和支持对应组件的副 OC 上依次执行：

```sh
ae-orbit stop
ae-orbit-install http://125.77.172.25:8080
reboot
```

重启后执行 `ae-orbit start`（已设置开机启动的机器会自动运行）。更新器保留 `/etc/ae-orbit.cfg`。必须保留 `inventory_mode="exact_only"` 和关闭库存事件的配置；重启让 OpenOS 清除旧模块缓存并重新上报能力。

## 查询与稳定性边界

流体只调用 `getFluidInNetwork({name=registry,amount=0})`，源质只调用 `getEssentiaInNetwork({name=tag,amount=0})`。绝不调用 `getFluidsInNetwork()` 或无参数 `getEssentiaInNetwork()`。启动时也关闭流体、源质的事件订阅，避免监听回调重建整网列表。

资源共用原有全组读额度、队列内存、响应包和过期限制。后台通常每四个物品/资源查询机会分配一个资源查询；仅有资源到期时可连续查询。流体可参与合成与清单；源质不参与合成，资源数量不混入物品历史。查询结果身份不同、含标签或数量无法精确表达时，保留旧观测并报告失败。

这消除了本采集器主动枚举整网的路径，不能保证 AE2、跨网络存储总线或其他模组永远不崩溃。若采集后仍出现原崩溃，需要新的完整堆栈确认实际触发路径。
