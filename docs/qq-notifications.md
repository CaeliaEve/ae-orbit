# QQ 联动

MaiBot 插件管理允许通知的群和私聊范围；AE Orbit 管理任务接收人、通知规则和持久发送记录。MaiBot 插件通过限定服务器组的独立令牌主动拉取任务，使用既有 SnowLuma 适配器发消息。无须新建 OneBot 连接，也不改变游戏服务器模组或 OC 采集方式。

## 使用

1. 插件市场打开「QQ 联动」，启用插件并生成连接令牌。默认「允许发送真实 QQ 消息」关闭；此时只保存通知，不发送。
2. 安装 `integrations/maibot-ae-orbit` 到 MaiBot 的 `plugins/ae-orbit-notifications` 独立仓库。部署代码与配置前先备份已有文件。
3. 在 AE Orbit 管理页生成独立连接令牌，将令牌和实际机器人 QQ 写入插件服务器的凭据文件（权限 600）。从 `config.example.toml` 创建插件 `config.toml`，设置 `[plugin].endpoint` 为当前 AE Orbit 的实际地址，设置 `credential_file` 为凭据文件路径。配置和凭据存放在部署机。
4. 加载 MaiBot 插件后，在插件扩展 → AE Orbit 通知渠道，刷新机器人群列表并勾选允许通知的群；可启用私聊副本并设置告警 @ 接收人。保存后自动同步群名到 AE Orbit。
5. 在物品详情或待提交清单设置完成通知，选择群、接收人，或手填 QQ。留空接收人则普通群播报；私聊副本需要接收人。
6. 更新主 OC 后，CPU 监控可对所有忙碌 CPU（包括未命名、重名 CPU）补设本次任务提醒。点击时先让 OC 确认原生 CPU 引用，再选择群和接收人。QQ 联动页可以修改或取消尚未结束的提醒。

## 任务识别

网页订单通过 OC 合成句柄分别报告完成、取消、失败和待确认。通知参数与订单受理清单一起固化，改变接收人后不能重用旧受理键。

合成 QQ 通知沿用库存页面的 NESQL 中文名称，发送前按原物品身份匹配，包含物品和流体。NBT 自定义名称优先保留；CPU 未提供完整 NBT 时沿用其上报名称。目录没有可靠匹配时保留原名。中文仅用于显示，不改变合成目标、数量或订单归属。

从游戏内发起的任意 CPU 任务没有公开的可靠完成句柄。新版提醒以本次会话和点击时 OC 保留的原生 CPU 引用跟踪，结束时仅通知「任务结束，结果未确认」。CPU 重连、失效、引用丢失或产物变化也会结束提醒并说明原因。同种 NBT 变种无法完全辨认，采样间隔内连续同产物任务可能无法区分；不能用它作为合成成功凭据。原生引用不保存到磁盘，OC 重启后必须重新选择，不能重新按索引绑定。

通知目标最多同时保留 16 个，每个目标约 10 秒读取一次，每次心跳最多分配 4 个目标，只检查其活动状态、忙碌状态和已有最终产物描述；不读取网络库存或合成过程清单。未保存的目标 2 分钟后过期。网页选择接收人期间快照编号更新不会改变已确认的目标。

CPU 名称或快照索引不能代替稳定的任务 ID。旧版主 OC 仍只允许唯一名称，并核对点击时产物与当前产物；新版原生引用提醒始终保持未确认模式。网页订单在下单时设置通知，可以利用可靠合成句柄确认成功。

## 投递

- 通知快照在业务状态事务中进入 `qq_outbox`，不依赖网页在线。
- 每轮最多领取 4 条作为传输批次，队列连续处理；不同查询没有冷却时间，也不人为间隔发送。群成员名单手动刷新并缓存。
- `queued → leased → sending → confirmed / uncertain`。租约过期的未开始发送记录可以重新领取；已开始发送的记录过期后进入待确认，不能自动重发。
- 插件先持久保存发送尝试，再请求开始发送，并在本地 SQLite 保存回执。进程重启后只上报回执或不确定状态，不重复发送。
- SnowLuma 群消息要求真实群序号回执。私聊只能确认平台接受发送，不能证明对方阅读或最终收到。
- 发群消息前验证每个接收人的群身份。在子网预警中可配置最多 10 位接收人，确认在群内的成员在同一条消息中被 @，跳过的接收人数写入投递记录。接收人留空时普通播报。 [子网预警配置](subnet-monitoring.md#监控和预警)
- 蓝波顿只发送低电量预警，电量恢复不向 QQ 播报。电容库页面的「设置电量阈值」可修改低于多少百分比触发、回升到多少百分比解除，以及持续秒数（0 为立即）。默认低于 20% 持续 30 秒触发，回升至 25% 解除并允许下一次预警，不播报恢复；每次低电量事件只通知一次。未发告警已恢复时跳过旧警报。关闭规则、观测丢失不算电量恢复，OC 上下线和读取异常不触发告警。
- 待发通知有效期 24 小时；成功、失败、过期记录保留 30 天，待确认保留供核对。
- 网络采集离线、恢复上线只在网页显示，不向 QQ 播报。旧的待发送上下线通知停止投递，已发送记录保留；合成异常和蓝波顿告警继续按各自规则通知。

## API

网页会话使用 `/api/v1/monitoring/groups/{group}/qq` 和 `/api/v1/networks/{network}/qq-reminders`。
连接令牌仅可访问 `/bridge/qq/v1/poll`、授权群的成员同步、已领取记录的开始发送与回执接口，不能访问 OC 或会员 API。

实施验证包含 PostgreSQL 事务回滚、重复事件、租约过期、发送不确定、跨服务器组和成员访问隔离，以及前端受理参数持久恢复。

## 渠道权限

MaiBot 的 `data/plugins/aeorbit.qq-notifications/channels.json` 持久保存允许群和私聊范围，管理页面只显示机器人已加入的群。网页不能增改允许群。连接器通过 `/bridge/qq/v1/channels` 同步完整名单；移除渠道时，原群待发通知与正在跟踪的提醒停用。每条消息发送前仍检查本地名单，名单同步失败时也不能继续向已移除的群发送。

## 手动改群号与电量查询

MaiBot → 插件扩展 → AE Orbit 通知渠道，可以手动输入群号并点击「添加群号」。机器人需要已加入该群；更换时取消旧群勾选，勾选新群后「保存并同步」。

授权群内发送 `/电量` 查询所有电容库，或 `/电量 设备名` 精确查询一台。每条不同的查询都会进入持久队列并唤醒发送器，不限制每群或每人的查询频率；同一条 QQ 消息的重复回调会去重。仅预览模式不发送消息。插件页面的「预览电量消息」可以直接查看内容，不会发消息。

QQ 电量消息仅显示设备名、储能和电量百分比，储能按 k/M/G/T/P/E EU 简写，省略内部编号、容量、输入输出、原因和时间。断线或过期数据标成最后观测；数据不存在时明确显示尚无有效观测。请求只读后端缓存，不增加 OC 或 ME 查询。


QQ 联动默认显示通知总览，包含本次任务提醒、最近发送与授权群。发送记录支持搜索通知、关键词或群号，筛选待处理及已发送；连接开关与高级令牌设置集中在连接设置。子网查询记录显示关键词标题，电量查询与预警各自使用明确名称。
