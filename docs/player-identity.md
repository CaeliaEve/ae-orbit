# 玩家身份与任务署名

团队玩家通过邀请码创建独立成员，填写游戏 ID 和密码。后续使用游戏 ID 与密码登录，浏览器只保存会话恢复信息，不保存密码或邀请码。原有成员令牌和管理员令牌继续可用，已有共享账号订单保持原归属。

## 团队使用

1. 管理员登录后打开“设置 → 玩家与团队”，可为自己的管理员账号绑定游戏 ID。
2. 选择要开放的网络、查看或下单权限、可注册人数，生成邀请码。代码只在本次生成后显示；有效期 7 天，人数上限 100，可随时撤销。
3. 玩家在登录窗口选择“加入团队”，填写游戏 ID、密码和邀请码。注册成功后自动登录。之后选择“玩家登录”。
4. 新生产任务和单项订单从后端登录成员取得署名，客户端不能指定下单人。普通成员默认查看“我的任务”，可以切换全组任务，控制权限仍仅限所有者或管理员。

游戏 ID 支持 3–16 位英文字母、数字和下划线，唯一性忽略大小写，显示保留原写法。它是团队自行声明的名字，不代表已经验证 Minecraft UUID。邀请成员不会获得管理员身份，也不会继承邀请码创建人的其他网络权限。

## 历史与恢复

任务在创建时保存下单人名字及固定成员 ID。修改游戏 ID、停用成员或更换密码不会把旧订单改归其他玩家。旧共享账号记录使用原成员名字，不猜测实际玩家。任务派发后产生的单项订单继续沿用该任务创建时的署名。

任务详情显示创建人及每次成功暂停、恢复、停止的操作人和时间。管理员处理他人任务明确标记为代操作，幂等重放不重复增加记录。普通玩家不能撤回其他成员的单项订单。

“玩家与团队”中可修改自己的游戏 ID 和密码；已有密码的账号需提供当前密码。管理员可重设成员游戏 ID 和密码、停用成员。身份或密码修改会退出其他浏览器会话。成员被停用或失去下单授权后，现有生产任务按原权限机制暂停，恢复权限不会自行继续。

草稿与本机请求记录以成员 ID 和网络 ID 分别保存。换人登录加载该成员自己的草稿，不转移上一人的清单。已经提交的任务保存在后端，换设备可以查看；尚未提交的本机草稿不会跨设备同步。

浏览器请求附带 `X-AE-Member` 身份检查。另一个标签页换人登录后，旧页面会要求重新登录并停止提交，避免共用 Cookie 导致草稿署名串人。身份或密码变更后，已在途的旧登录也不能重新建立旧身份会话。

## 接口与存储

- `POST /api/v1/session` 接受原有 `{token}`，或互斥的 `{game_id,password}`。
- `POST /api/v1/players/register` 接受 `{game_id,password,invitation}`。
- `PUT /api/v1/me/player` 接受 `{game_id,current_password,password}`，新密码留空保留，成功后返回新会话。
- 管理员使用 `GET/POST /api/v1/player-invitations`，以及 `DELETE /api/v1/player-invitations/{id}`；创建请求为 `{network_id,can_craft,max_uses}`。
- 管理员 `PUT /api/v1/members/{member}/player` 接受 `{game_id,password}`，不返回明文密码。
- 当前成员增加 `game_id`、`password_login`；任务与订单增加 `owner_name`；任务详情增加 `activity`。

密码至少 10 个字符，最多 256 UTF-8 字节，以随机 16 字节盐和 PBKDF2-HMAC-SHA256（600,000 次）保存。邀请码只保存散列，人数消耗与成员及权限创建在同一事务中。密码登录和注册限制并发 2 次、同一来源 5 分钟最多 60 次，避免计算挤占 OC 通信。

公网实例应通过 HTTPS 使用密码登录；本项目的 HTTP 配置可用于本机或受信任网络，部署管理员需要配置 TLS 入口。仍持有旧共享管理员令牌的人保留原管理员权限；完成玩家账号迁移后，应由管理员更换旧令牌，不能把填写不同游戏 ID 当成权限隔离。
